# Site Meetin-OS

Le site Next.js sert les téléchargements à `/telecharger` et les premiers pas à `/onboarding`. L’app Mac utilise `/api/agent-access` pour vérifier le code d’équipe et lire l’état de la configuration, puis `/api/agent-prepare` et `/api/agent-execute` pour préparer et lancer une tâche. Depuis ce dossier, lance `npm ci`, copie `.env.example` vers `.env.local`, puis lance `npm run dev`. Génère `MEETIN_DEMO_TOKEN` avec `openssl rand -hex 32` pour protéger les routes d’intégration.

## Comptes, transcription et abonnement Mac

1. Dans le [projet Supabase de l’équipe](https://supabase.com/dashboard/project/lqqkgyvwilltwgkxlirb), applique la [migration des comptes et quotas](../supabase/migrations/20261107190000_meetin_accounts_and_quota.sql). Active la connexion par e-mail avec confirmation. Configure **Confirm signup** et **Magic Link** pour afficher `{{ .Token }}`, le code à six chiffres que l’app demande. Pour envoyer le code à des utilisateurs hors équipe, configure un [serveur SMTP](https://supabase.com/docs/guides/auth/auth-smtp). [Connexion Supabase par code e-mail](https://supabase.com/docs/guides/auth/auth-email-passwordless)
2. Renseigne `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY` et `SUPABASE_SECRET_KEY` côté serveur. La clé secrète moderne ou l’ancienne clé `service_role` est acceptée. Dans [Supabase Vault](https://supabase.com/docs/guides/database/vault), utilise les noms `gladia_api_key`, `hai_api_key` et `devin_api_key`. Si Lenny a déjà créé les entrées, vérifie leurs noms sans copier les valeurs. Les variables serveur `GLADIA_API_KEY`, `HAI_API_KEY` et `DEVIN_API_KEY` restent possibles et priment sur le Vault.
3. Configure `MEETIN_WEB_URL` avec l’adresse publique du site. Pour le direct sur Vercel, renseigne `MEETIN_GLADIA_LIVE_URL=wss://<même-hôte>/api/gladia-live` et vérifie que la [prise en charge WebSocket](https://vercel.com/kb/guide/real-time-chat-websockets) est disponible sur le projet. En local, utilise `ws://localhost:3001/api/gladia-live` avec `npm run live:local` dans un second terminal et le site sur `http://localhost:3000`.
4. Pour activer Premium, configure `STRIPE_SECRET_KEY`, `STRIPE_PRICE_ID` (tarif récurrent) et `STRIPE_WEBHOOK_SECRET` dans le même environnement Stripe. Déclare `/api/stripe-webhook` pour `checkout.session.completed` et `customer.subscription.created`, `.updated`, `.deleted`, `.paused`, `.resumed`. Active le portail client Stripe pour **Gérer l’abonnement**. Commence en environnement de test. Le serveur vérifie la signature et le statut de l’abonnement avant de mettre à jour le plan. [Webhooks Stripe Billing](https://docs.stripe.com/billing/subscriptions/webhooks)

**Gratuit : 15 min audio par mois. Premium : 300 min.** Le compteur repart le premier du mois à 00 h UTC. Le serveur mesure l’audio envoyé : une minute de micro et une minute de son de l’appel comptent pour deux minutes. Le direct et la transcription après l’appel partagent le quota. Les volumes se règlent en base dans `meetin_private.quota_plans`. En cas de quota épuisé, le carnet et la capture locale restent accessibles.

Le site sert à installer l’app et à ouvrir **Compte** ou **Intégrations** avec l’adresse du serveur préremplie. La connexion, le solde et le lancement de Stripe Checkout se font dans **Compte** sur Mac. Le site ne contient pas de carnet.

## Intégrations de l’agent

- **Holo** utilise la clé H et, facultativement, `HAI_MODEL` pour préparer une tâche depuis une demande ou un extrait. Il pose une question si le résultat ou la cible est ambigu. La préparation n’ouvre aucune session d’exécution.
- **Linkup** utilise `LINKUP_API_KEY` pour répondre à une question publique avec des liens vers les sources. Cette route serveur reste disponible pour un futur branchement dans l’app.
- **Devin** traite les tâches de code sans interface tierce. Configure `DEVIN_ORG_ID`, la clé d’un utilisateur de service v3 et `DEVIN_REPO`. Restreins les accès Git du compte de service à ce dépôt. Le lien de session permet de suivre le travail et de retrouver la PR éventuelle.
- **H Computer Use** crée ou modifie une fiche dans le tableau de test HTTPS défini par `HAI_COMPUTER_USE_URL`. Pour Trello, `HAI_BROWSER_PROFILE_ID` doit désigner un profil H dédié, connecté au compte de test. Sans ce profil, la proposition reste disponible dans l’app et le serveur attend la configuration avant de lancer H. Après configuration, utilise **Vérifier les accès** dans **Intégrations**. L’app affiche **En cours** et appelle `/api/agent-trello-status` avec le reçu signé du lancement. Elle affiche le lien direct quand H a terminé et confirmé la relecture de la fiche sur le tableau approuvé. [Profils navigateur H](https://hub.hcompany.ai/agents-api/browser/profiles) · [Résultat d’une session H](https://hub.hcompany.ai/agents-api/sessions/retrieve)

Saisis le code d’équipe dans **Intégrations** sur Mac. L’agent garde son code distinct du compte de transcription. Pour la recette locale, `npm test` exécute les intégrations avec des réponses simulées et `npm run build` compile le site.

Le bouton **Confirmer et lancer** dans l’app approuve la proposition affichée, sa destination et le contexte associé pour quinze minutes. Modifier la demande exige une nouvelle préparation. H déduplique la création de session avec l’identifiant de validation. Pour Devin, la protection contre les doubles clics fonctionne dans l’app et sur une même instance serveur. Si le lancement est incertain, vérifie la session dans le service avant de préparer une nouvelle validation.

[H Computer Use](https://github.com/hcompai/hai-agents-ts) · [API Devin](https://docs.devin.ai/api-reference/getting-started/teams-quickstart) · [Linkup Search](https://docs.linkup.so/pages/documentation/endpoints/search/reference) · [Stripe Checkout](https://docs.stripe.com/api/checkout/sessions/create)

Pour publier le site, le dossier racine Next.js est `web`. `brand-tokens.css` reprend les tokens officiels de `../brand/tokens.css` dans le périmètre du build web. En cas de changement de DA, mets les deux fichiers à jour ensemble.
