# Meetin-OS pour Windows

Le carnet est compatible avec Windows 10 ou 11 (x64) et .NET Framework 4.8 ou ultérieur. Cette version de .NET est déjà incluse dans Windows 10 22H2 et Windows 11. [Prérequis Microsoft](https://learn.microsoft.com/fr-fr/dotnet/framework/install/on-windows-10)

1. Sur le site, clique sur **Installer sur Windows** et ouvre `Meetin-OS-Windows.exe`. L’assistant installe Meetin-OS pour ton compte, sans droits administrateur. Windows peut signaler cet installateur de test non signé.
2. Ouvre **Meetin-OS** depuis Démarrer. Pendant un appel, clique sur **Commencer à enregistrer** pour ouvrir la fenêtre de réunion (notes, transcription en direct, compteur), puis sur **Arrêter** pour retrouver la réunion et ses pistes dans **Réunions**. Dans **Paramètres**, **Détection Zoom** surveille les fenêtres de Zoom toutes les 2 s et propose de lancer l’enregistrement quand une réunion commence ; comme sur Mac, l’enregistrement reste manuel.
3. Dans **Paramètres**, saisis ta clé Gladia. Avec **Transcription en direct**, l’audio part en continu vers l’API live de Gladia pendant l’enregistrement (une session par piste, `fr`/`en`, reconnexion automatique, réunion marquée « Incomplète » en cas de panne durable) et le texte s’affiche dans la fenêtre de réunion. **Transcrire avec Gladia** envoie les pistes après coup et affiche les passages dans l’ordre. La clé est gardée sur le PC, chiffrée pour ta session Windows (DPAPI) dans `%LOCALAPPDATA%\Meetin-OS\gladia.key`. Tu peux aussi ouvrir un WAV, MP3 ou M4A depuis **Réunions**.
4. Dans **Intégrations**, saisis l’adresse du site Meetin-OS (https, ou http seulement en local) et le code d’accès de l’équipe (chiffré DPAPI dans `agent.key`). La page affiche les accès Gladia, Trello, Devin et planning renvoyés par `agent-access`. Quand le direct tourne et que l’agent est connecté, les tâches sont détectées toutes les 15 s (`agent-detect`) et affichées en cartes **À valider** : Confirmer et lancer, Modifier, Ignorer. Rien n’est lancé sans ta validation.
5. La page **Agent** reprend celle du Mac : demande + extrait de réunion → **Préparer la tâche** (`agent-prepare`, questions de précision) → **Confirmer et lancer** vers Devin ou H Computer Use (`agent-execute`). Le lien renvoyé n’est ouvert que s’il pointe vers `app.devin.ai` ou `platform.hcompany.ai`.

**Pendant l’enregistrement**, la barre d’enregistrement de la marque (point rouge, chrono, barres de niveau qui suivent le volume du micro et de l’appel, Pause, Arrêter) remplace le bouton Arrêter dans la fenêtre de réunion et sur l’Accueil ; **Ctrl+R** démarre ou arrête l’enregistrement comme ⌘R sur Mac. Les passages du micro portent ton nom complet Windows (sinon ton nom de session, sinon « Vous ») dans le direct et la transcription. Les réunions ont pour titre par défaut « Réunion du 8 novembre à 19:14 » (« Réunion Zoom du … » si Zoom était détecté). Des notifications Windows signalent une tâche à valider (« À valider : … »), un direct interrompu et une réunion Zoom détectée quand l’app n’est pas au premier plan ; un clic ouvre la page concernée. Sur la fiche d’une réunion, **Nouvel enregistrement** lance une capture et **Afficher la réunion** ramène la fenêtre de réunion en cours. **Ouvrir un enregistrement** ajoute le fichier (WAV, MP3, M4A…) à l’historique sans le déplacer ; supprimer cette réunion n’efface jamais le fichier d’origine. Comme sur Mac, changer de réunion, importer ou supprimer est bloqué pendant un enregistrement, une transcription ou une action de l’agent.

**Renommer ou supprimer une réunion** : dans **Réunions** (ou les réunions récentes de l’Accueil), clique sur **⋯** au bout de la ligne, ou fais un clic droit, puis choisis **Renommer…** ou **Supprimer…** ; les mêmes boutons sont sur la fiche de la réunion. Un titre vide est refusé, le nouveau titre est écrit dans `titre.txt`. **Supprimer** demande toujours une confirmation et envoie le dossier de la réunion (audio, notes, transcription, tâches) dans la Corbeille de Windows, d’où il se récupère. La suppression est bloquée pendant un enregistrement, une transcription ou une action de l’agent.

L’interface reprend celle du Mac : thème nuit, barre latérale (Accueil, Réunions, Agent, Intégrations, Paramètres, Compte), accueil « Prêt pour la prochaine réunion ? » et historique des réunions lu dans le dossier `Recordings` (notes, transcription et tâches proposées enregistrées à côté des WAV). Différences restantes avec le Mac : contrôles dessinés en WinForms (pas de polices de marque embarquées), pas de notifications Windows pour les tâches ou les pannes du direct, détection Zoom par titre de fenêtre (`Zoom Meeting` / `Réunion Zoom`) sans accessibilité.

Windows ne demande pas l’accès au micro pour une app de bureau. Si **Autoriser l’accès au microphone sur cet appareil** ou **Autoriser les applications de bureau à accéder à votre microphone** est désactivé dans Paramètres > Confidentialité > Microphone, le carnet enregistre seulement `appel.wav`, le signale et propose d’ouvrir ces paramètres. L’appel doit utiliser le micro et la sortie audio définis par défaut dans Windows. Le son de la sortie peut inclure d’autres applications. Après un essai, **Voir les pistes** ouvre le dossier contenant `micro.wav` et `appel.wav` lorsqu’un signal a été reçu. Les enregistrements sont conservés dans `%LOCALAPPDATA%\Meetin-OS\Recordings`.

## Construire l’installateur

Depuis la racine du dépôt, avec le SDK .NET 10 et le compilateur NSIS (`makensis`) :

```sh
dotnet restore windows/Meetin-OS.csproj --locked-mode
dotnet build windows/Meetin-OS.csproj -c Release --no-restore -o windows/.build/payload
makensis windows/installer.nsi
```

Le dernier appel génère `web/public/downloads/Meetin-OS-Windows.exe`, le fichier que sert le site. Le build peut se faire sur Mac ou sur Windows : le projet fixe le runtime `win-x64`, donc `packages.lock.json` est le même sur les deux systèmes, et les chemins du script NSIS utilisent `\`, accepté par `makensis` partout. Sur Windows, [NSIS](https://nsis.sourceforge.io/Download) existe aussi en archive ZIP à dézipper sans droits administrateur. La version se change à deux endroits : `Meetin-OS.csproj` et `APP_VERSION` dans `installer.nsi`. Le workflow Windows vérifie sur un runner l’installation, le raccourci et l’ouverture du carnet.

## État des tests

- Test simulé : `dotnet run --project windows/tests/GladiaSmoke.csproj` vérifie avec un faux serveur Gladia l’envoi des deux pistes, l’ordre des passages et le rejet d’une mauvaise clé. Aucun appel réseau réel.
- Essai réel (8 novembre 2026, Windows 10 22H2, écran à 125 %) : installation de `Meetin-OS-Windows.exe` 0.1.1, ouverture du carnet, enregistrement avec une voix de synthèse dans les haut-parleurs. Avec le micro refusé par Windows, l’ancienne version s’arrêtait sur « Accès refusé (E_ACCESSDENIED) » sans rien enregistrer ; la version corrigée garde `appel.wav` et indique le réglage à activer. Micro autorisé : `micro.wav` et `appel.wav` sont écrits.
- Essai réel après la refonte de l’interface sur le modèle du Mac (thème nuit, barre latérale, accueil, réunions, paramètres, compte) : enregistrement depuis « Commencer à enregistrer », deux pistes écrites, réunion ouverte dans la page détail avec ses notes.
- Essai réel après le portage du direct, des tâches et de l’Agent (8 novembre, même PC, sans clé Gladia ni code d’équipe) : fenêtre « Réunion en cours » avec compteur, pastille « Direct : clé Gladia manquante », notes et panneau de transcription ; `micro.wav` et `appel.wav` écrits (≈ 13 s), réunion ouverte dans la page détail. Pages Agent et Intégrations affichées.
- Non vérifié en réel : la transcription Gladia (différée et en direct) depuis le carnet Windows (nécessite une clé saisie dans Paramètres), la détection de tâches et le lancement vers Devin ou H (nécessitent un serveur Meetin-OS et un code d’équipe), la détection Zoom (Zoom non installé sur ce PC) et l’avertissement SmartScreen en installation interactive. Le code du direct, du détecteur et du client agent compile et suit les mêmes contrats que le Mac (`mac/LiveTranscription.swift`, `mac/TaskDetection.swift`, `mac/AgentClient.swift`), mais aucun appel réseau réel n’a été fait depuis Windows.

Pour la recette audio, utilise un vrai PC Windows avec deux personnes en appel. Vérifie les deux WAV séparément, puis lance Gladia et compare l’ordre des passages.
